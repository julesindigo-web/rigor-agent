# HRAS product quality profile

Create testable acceptance criteria from user intent. Choose a quality profile proportional to domain and risk. Evaluate complete user workflows, data/API correctness, security/privacy, error/empty/loading feedback, accessibility, responsive behavior, visual hierarchy, performance under measured targets, reliability, observability, operations, license/dependency provenance, documentation and maintainability. Use independent oracles for critical calculations/domains. Avoid arbitrary features and architecture complexity. Compare the shipped artifact to the final requirements and tests, not merely to the plan. Report which quality dimensions were measured, reviewed qualitatively, unavailable, or not applicable. Do not call a product a “masterpiece” or production-ready without approved criteria and evidence.
